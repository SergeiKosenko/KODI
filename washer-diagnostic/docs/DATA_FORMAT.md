# Формат базы JSON, версия 1

Импорт находится в приложении: **Каталог и база → Ваша рабочая база → выбор файла**. Пример ниже — исключительно описание формата, вымышленные данные не следует применять к технике.

```json
{
  "schemaVersion": 1,
  "entries": [
    {
      "id": "demo-model-error",
      "brand": "ДЕМО, не реальная техника",
      "models": ["DEMO-MODEL-1"],
      "codes": ["DEMO01"],
      "system": "drain",
      "title": "Пример описания кода",
      "summary": "Симптом согласно документу.",
      "scope": "Полная модель, продуктовый код, версия электроники и ограничения.",
      "causes": ["Возможная причина по руководству"],
      "checks": ["Проверка по руководству"],
      "source": {
        "title": "Название подлинного документа (здесь демонстрационный пример)",
        "url": "https://example.org/demo-not-a-real-manual.pdf",
        "page": "стр. 12, ревизия документа"
      }
    }
  ],
  "procedures": []
}
```

Замените демонстрационные поля реальной, проверенной информацией и ссылкой. `models: []` разрешено только для карточек ошибок общего характера; такие карточки не подтверждают совместимость с произвольной моделью. Указанная модель ограничивает показ импортированной карточки точным нормализованным совпадением. Пробелы, двоеточия, точки, подчёркивания и дефисы при сравнении удаляются, регистр не учитывается; значимые различия ревизий должны сохраняться в буквенно-цифровой части модели или явно описываться в `scope`. Для более строгого разделения версий используйте полный код изделия в поле модели.

Допустимые `system`: `fill`, `drain`, `door`, `heat`, `motor`, `level`, `leak`, `balance`, `foam`, `comm`.

Для `procedures` запись содержит:

- `id`, `brand`, `title` — непустые строки;
- `models` — непустой список точных моделей; маски не поддерживаются;
- `scope` — область применимости, включая панель, код изделия и ревизию;
- `prepare` — непустой список действий подготовки;
- `steps` — непустой список шагов входа/работы;
- `exit` — безопасная процедура выхода;
- `source` — как в карточке ошибки.

Не копируйте комбинацию входа от внешне похожей машины. Включайте ограничения запуска, ожидаемую индикацию, условия прекращения проверки и таблицу этапов только при наличии документации для этой электроники.

`id` должны быть уникальны в одном пакете. При повторном импорте запись с тем же `id` заменяется. HTTPS-ссылка обязательна, но её наличие не доказывает авторство производителя. Поле `status` из файла игнорируется: импорт не может объявить себя подтверждённым.

Резервная копия имеет `backupVersion: 1`, `custom` (пакет), `saved` (список id), `notes` (объект id → текст), `exportedAt`. При восстановлении база дополняется/обновляется, а избранное и заметки заменяются содержимым копии. Перед импортом новой копии экспортируйте текущие данные. Резервная копия без пользовательских карточек допускается для переноса заметок и избранного.
